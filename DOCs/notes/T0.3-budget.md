# T0.3 CPU budget (proxy, 2026-11-15)

What is known without hardware:

| Engine             | Cost, eight held notes, WebAssembly build (`tests/cpu_proxy.mjs`) | Memory                                                                    |
| ------------------ | ----------------------------------------------------------------- | ------------------------------------------------------------------------- |
| SYN (analog voice) | 1.00 (reference)                                                  | voice core                                                                |
| FM2 (4-op)         | 0.76                                                              | 8 voices x 120 B in `voice_t.ev`                                          |
| ORG (drawbar)      | 0.69                                                              | per-part rotor state, 4 x 8 voice states, a few hundred bytes             |
| SP (samples)       | 0.67                                                              | 122 KB ADPCM + 25 KB synthesised sets in the image (flash, read in place) |
| FM6 (6-op)         | 1.00                                                              | 8 x 244 B notes + per-part patch/LFO state, about 4 KB RAM                |

Conclusions and limits:

- The ratios say the plugged engines cost about what the analog voice costs. The old SMKSYNTH core ran its analog voice with headroom, so
  the same voice count of another engine is expected to fit. This is a ratio on a desktop CPU, not cycles on the device.
- The adapter renders 32-sample windows every second 16-sample block: the load comes in alternating blocks (every second block does twice
  the work for the engine voices). A deadline miss would show first as an overrun in the panel check.
- The voice pool is shared (8 voices). Four parts with eight voices each is not possible; worst cases are bounded by that pool.
- Not measured: real cycle counts, flash read stalls for the sample data, the effect units, USB audio load.
