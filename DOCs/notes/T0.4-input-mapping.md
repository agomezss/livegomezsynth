# T0.4 - Input mapping (done, 2026-11-14)

## Finding: the layout we want already exists in the code base, and I had it backwards

The SMKSYNTH user doc `SMK37.md` (K1 = MASTER, K2-K4 = SELECT/ALGO/PRESETS, K5-K8 = knobs) is **stale**. SMKSYNTH 1.2.0 includes the PF12 change
(`SMKSYNTH/pf12-controls.patch`, `PF12-LEIA-ME.md`; the 1.2.0 manual says the same): **K1-K4 = screen parameters, K5 = tempo/contextual,
K6 = part, K7 = preset, K8 = MASTER**, and `hal/smk_input.h` has `SMK_ENC_MASTER 7u`. That is exactly D-03. My earlier statement that the owner's
numbering was "reversed" was wrong; `IDEA.md` was right. (`00-decisions.md` D-03 and `01-source-analysis.md` are corrected.)

## Facts

| Item               | Value                                                                                                                                                                                                                                           |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Encoders           | 8, all endless quadrature (`SMK_ENCC` table in `hal/smk_input.h`, index 0..7 = K1..K8 left to right), decoded per frame (1.6 ms), `fm1_enc_take(i)` returns the detents since the last call                                                     |
| MASTER             | virtual pot in the HAL: `smk_master` 0..1023, 24 per detent, default 724 (~70%); `platform_poll()` turns it into `master_q12`, applied in the audio IRQ path (`fm1_alnk0_irq`) **after** `app_audio()`, so the host harness cannot hear it      |
| Master persistence | SMKSYNTH also saves the master at manual store and restores it at boot (`smk_boot_volume_capture/restore`, in `obervave.c`). The skeleton does not yet; decision for the new storage (T1.9): keep that rule (D-03 says "same rule as SMKSYNTH") |
| Sustain            | physical pedal input on mux C address 6, with startup polarity detection (`smk_sustain.h`, SMKSYNTH 1.2.0 notes); to be wired in T1.4                                                                                                           |
| Soft takeover      | faders use catch/jump logic in `obv_smk.h`; reuse the idea in T1.8                                                                                                                                                                              |

## Done

- `firmware/src/lgs_input.h`: logical names `LGS_K1..LGS_K8` (+ a `_Static_assert` that K8 is the HAL's master encoder) and `lgs_knob(k)`, which refuses K8 so the
  master pot is never double-consumed.
- Skeleton `lgs_app.c` uses it: K1-K4 edit CUTOFF / RESO / ENV AMT / RELEASE (clamped 0-127, 2 per detent), K7 browses the factory programs
  (loading resets the tweaks, D-07), K5/K6 are drained and unused. Verified on the host harness with `tests/scripts/knobs.txt`
  (screen shows the four values).
- Not verifiable here: K8 on the host (needs the simulator, T0.6) and on hardware (panel check screen of the old firmware shows each encoder; port it
  in T0.7b).
