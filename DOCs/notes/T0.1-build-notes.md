## Findings (they change the plan)

1. **App slot is 320 KiB, not ~560 KiB.** `APP_SLOT = 0x50000` (327,680 B). Current image 224,880 B, so only **~102 KB free**
   for code + samples. SMKSYNTH 1.2.0 keeps the user data bank (`SMK16P1`) at `0x57000..0x9CFFF` (280 KB) right after the
   app and a restore journal at `0x55000`. The loader may write all of `0x4000..0x9CFFF`, so the slot can grow only if we
   shrink or move that data region (a package/linker constant change, not a loader change).
2. **RAM is nearly full:** `.data+.bss` 95,392 of 98,304 B (2.9 KB free); pool 328,368 of 344,064 B (15.7 KB free).
   Four heavy engine arenas (FM, sampler, ...) will not fit without freeing RAM or sharing arenas. This raises R-03 and R-04.
3. **Unused flash we may own:** `FL_SMP 0xC2000..0xE9FFF` (160 KB) is allow-listed; SMKSYNTH uses part of it for pattern slots
   (`0xC2000-0xE1FFF`). The loader cannot install data there, so factory samples still have to live in the app image
   (or in the loader's record window `0x9D000..0xBFFFF`, to be investigated).
4. **Display font is proportional** (`text_w(&FONT_S, ...)`), so there is no fixed 30-column grid: the UI spec must lay out by
   pixel width. Screens are drawn with `cv_text`/`cv_rect` on a 240x240 canvas.
5. **Flash map confirmed** (`firmware/hal/fm1_flash_map.h`): head `0-0x3FFF` never; app `0x4000-0x9CFFF`; store `0x9D000-0xBAFFF`;
   OTA staging `0xBB000-0xBFFFF`; BTIF/USRTRIM `0xC0000-0xC1FFF` never; FL_SMP `0xC2000-0xE9FFF`; stock USR `0xF4000-0xFDFFF`
   never; key_mac `>= 0xFF000` never. Compile-time asserts plus a second runtime guard (`FL_GUARD`). JEDEC ids `0xEB6014`/`0x856014`.
6. **Host tests do not run natively on macOS** (ELF `section(".pool")` attributes are rejected by Mach-O). Run them in the
   Linux container. `docker run --rm --platform linux/amd64 -v "$PWD:/work" -w /work lgs-hosttest sh -c '...'`.
7. **Test status on the pristine tree (in the container):**
   - 24 of 24 maintained control/feature tests pass (`endless`, `midi_*`, `seq_dp2`, `patterns16`, `drum_pads`, `save_*`,
     `smk_boot_header`, `physical_controls`, ...).
   - SMK-37 flash-map guard test passes.
   - `tests/smk_ui_test.py` reports **12 failures**: it is a legacy test that still expects the pads to be sequencer steps by
     default, while U1 made bank 1 Performance/Favoritos. Treat as stale upstream, do not use as a regression gate.
   - `run_physical_controls_tests.sh` with ASAN is killed (OOM, Colima has 2 GiB). Run its tests without ASAN or raise the
     VM memory.
   - `tests/run_tests.sh` (legacy) needs both FM-1 and SMK builds; not used.
